The up-to-date looper design lives in the in-repo doc: **`DrivenByMoss/docs/looper-design.md`**. The user's goals have evolved over development, so a few requirements there differ from earlier ones in the history below — where they conflict, follow the current doc (e.g. it dropped flat/end-following banks, the emptiness-based spawn, auto-cleanup, and monitor-at-end). The history and lessons below are still valuable context.

Quick essentials:
- Branch `fancy-apc40mkii-looper`; Bitwig API 25. Compile-check: `mvn -o -f "C:\Users\isaac\DrivenByMoss (isaacdnew fork)\DrivenByMoss\pom.xml" compile` (pass -f absolute path; PowerShell cwd resets). User builds via release-windows.cmd + tests in Bitwig.
- Standing directives: NO arbitrary timers (omit any feature needing one); NO auto-cleanup of empty layers (accept clutter); event-driven only.
- GOTCHA (RESOLVED 2026-06-05): a group's child track bank includes the group's own **master/sum bus** as a TRAILING child (`getType()==ChannelType.MASTER`, named "<Group> Master", and `canHoldAudioData()` returns TRUE for it!). So a Monitor+Template group presents 3 child items (2 real + master) — that was the real cause of the earlier "getItemCount looked wrong" confusion. IDENTIFY TRACKS BY TYPE, not heuristics: monitor/template/layers must be `getType()==ChannelType.AUDIO` (NOT `canHoldAudioData()`, which the master passes); stop the layer scan at the first `MASTER`. `getType()` returns UNKNOWN (not an error) for a non-existent track, and never returns GROUP_OPEN (that's display-only), so `type==GROUP`≡`isGroup()`. The OLD finalize once renamed the master to "Layer 2" by writing to child[2] when it was the master — the AUDIO-type guard now prevents touching it.
- BITWIG QUIRK (confirmed 2026-06-05, reproduces on a plain audio track with the script OFF): when a launcher recording STOPS (via the normal end-record action — triggering the recording slot to stop), Bitwig can treat the clip as a ONE-SHOT — it plays a single pass of its content and stops (slot shows a queued stop), even with the clip's loop attribute ON. Nothing is known to be special about HOW the recording is ended (the manual repro was just pressing the clip to stop). Launching the FINISHED clip loops normally. **We DO NOT KNOW the exact condition that decides loop-vs-one-shot** — it tends to happen with VERY SHORT recordings and longer ones loop fine, but whether the boundary is a time/beat threshold, crossing a loop/quantization point, or some other Bitwig state is UNCONFIRMED. FIX = re-launch the clip the instant recording stops. Class `RecordedClipLaunchFixer` (apc pkg; NOT named "auto-looper" — it doesn't record layers, it fixes the launch). GESTURE-DRIVEN (not state-driven): re-launches a slot ONLY if the press that ended its recording `scheduleRelaunch(trackPos, scenePos)`'d it — so transport-stop (spacebar), stop-clip button, etc. do NOT re-launch (fixing a bug where they did). Scheduled identity = clip's `(track.getPosition(), slot.getPosition()=sceneIndex)` so horiz/vert scroll can't match the wrong clip. The looper's `handlePad` finish schedules the recording LAYER's child slot (NEVER the GROUP slot — launching a group slot launches the whole sub-scene, another fixed bug); general session clips are scheduled in `SessionView.onGridNote` when a pressed pad's slot is recording. Watcher = `watch(track)` registered over session bank + looper child banks; on isRecording→false: if scheduled (consume it) AND `transport.isPlaying()` AND `!track.isGroup()` AND `hasContent` → `slot.launchWithOptions("none","continue_or_synced")` (user-chosen) = cancels the queued stop mid-first-pass so it keeps looping, independent of configured launch quantization. `LooperManager.stopColumn` calls `launchFixer.cancelScheduledForTrack(childPos)` for every child so a stop can never be undone by a pending re-launch (backstops unknown edges). New framework methods: `ISlot.addIsRecordingObserver(IValueObserver<Boolean>)` and `ISlot.launchWithOptions(String quantization,String launchMode)` (impl SlotImpl, no-op EmptySlot). STAGING-LAYER MGMT: `finalizeOrEnsure` was renamed `maintainStagingLayer(column)` (runs every rescan on a valid group): (0) disarm child[4] EVERY rescan (only staging child[2] + recording/most-recent child[3] stay armed; every layer passes child[3]→child[4]→out-of-5-wide-window, so disarming the single index child[4] each rescan disarms each layer before the next duplicate pushes it out — fixed a bug where the FIRST layer stayed armed: the old one-shot disarm-in-finalize coincided with child[4] being the non-audio master, then the layer left the window unreachable; can't iterate past child[4] since deeper layers are out of window); (1) finalize a pending duplicate (when child[2] is AUDIO+template-named → arm if armed, clear pending); (2) ensure a staging layer ONLY from a CONFIRMED state — child[2]==MASTER (no layers) OR child[2]==AUDIO+hasContent (staging deleted, recorded layer slid up) — NEVER on UNKNOWN/absent (this fixed a bug where horizontally paging an expanded group to layer tracks then back created a spurious "Layer 1": the child bank repopulates async, child[2] read UNKNOWN mid-load and the old `!=AUDIO` condition duplicated); (3) name child[2] = `prefix + (parseTrailingNumber(child[3])+1)`, or `prefix 1` if child[3] not AUDIO — "one greater than the layer to its right," kept current every rescan, idempotent. # Earlier process & lessons (context; some goals here have since changed)

Goal: add audio overdub to the APC40 MkII clip launcher in DrivenByMoss (Bitwig has no native audio-clip overdub). Repo: `DrivenByMoss/` subfolder (the git repo). As of 2026-05-30 this is design-only; no code written yet.

**Hard API constraint:** Bitwig controller API (extension-api v21) CANNOT read or set audio routing at runtime. `SourceSelector` only has audio-on/off + note-on/off booleans; no AudioInput/RoutingDestination classes. So routing is never scripted — it is pre-wired in a project template, and the script only orchestrates arm/monitor/record/duplicate.

**Core trick — infinite via duplication:** Bitwig `duplicate()` (Ctrl+D / `IChannel.duplicate()`) preserves input+output routing AND monitor mode, but NOT arm state (clone is always unarmed). Verified by user. So each overdub layer = duplicate an empty pre-wired "spawn" template track inside a group, then arm+record into the clone. Unlimited layers, zero scripted routing.

**Topology:** One Bitwig group track = one APC column = one logical looper "voice". Only ONE pad/scene active per column at a time (mutually exclusive loops; launching one stops the others' child tracks explicitly, since layers span different child tracks). A loop's layers = the scene-S clips across the group's duplicated child tracks, summed at the group output. Pads interact with the NESTED child tracks, not the group master.

Group children: (1) a MONITOR/source track (live monitoring ON + the audio source the layers record from), (2) a SPAWN template track (empty, monitor OFF, pre-wired to record from the monitor track), (3) the recorded LAYER tracks (duplicates of spawn). Monitor track lives INSIDE the group so its existence can be validated; group output = monitor(live) + playing layer clips. Layer tracks keep monitor OFF (still record fine). Re-patching the interface only touches the monitor track. When duplicating spawn, clone inherits the spawn name → script renames each fresh layer (e.g. "Layer N") and treats the exact-named empty track as the spawn.

**Length:** `IClip.getLoopLength()` returns beats but lives on a cursor clip (follows cursor track's focused slot), not on `ISlot`. Plan: cache the base-unit length when a loop's first (free-length) layer is recorded; use a dedicated cursor track/clip so measuring doesn't yank user selection. Length-locking an AUDIO overdub is enforced by the script stopping the record at a loop boundary (`host.scheduleTask` + `transport.getPosition()`/`getQuartersPerMeasure()`), NOT by the existing "new clip length in beats" setting (that path makes NOTE clips only).

**Two length concepts — FINAL NAMES = word / story:** WORD = length of the loop's FIRST layer (immutable while loop exists; LIFO deletes it last); = the "word" option of the selectable auto span. Fields like `wordLengthInBeats`. STORY = current/compound loop length = MAX of all current layers' lengths; grows when mode-(c) records a longer layer, and is recomputed (reverts) on every delete; always a whole number of words. Fields like `storyLengthInBeats`. User's "base unit that grows/reverts on delete" = STORY. Each layer length = integer multiple of the STORY at record time → running max always divisible by every layer → phase-locks through deletes. DELETE-LAST removes newest layer (LIFO); story = max of remaining. Selectable auto-overdub span setting: WORD | STORY.

**UI / controls:**
- Repurpose APC40 SOLO buttons (`ButtonID.ROW2_1..8`, `SoloCommand`, APCControllerSetup.java:250) as per-column overdub-mode toggles.
- Overdub mode ON: empty pad → record new free-length loop (stock armed-empty-slot path, SessionView.java); pad WITH content → begin overdubbing that loop (duplicate spawn, record length-locked layer). Mode OFF = stock behavior.
- Delete-slot combo in overdub mode = delete last (newest) layer; deleting last remaining layer deletes the loop.
- Looper groups identified by a customizable settings TEXT FIELD (substring of group name). THREE configurable name settings: group-name match, required spawn-track name, required monitor-track name. Script validates STRUCTURE + child NAMES (group exists; contains a track named per spawn-name and one per monitor-name; spawn empty/monitor-off/canHoldAudioData) — CANNOT validate routing.

**Overdub length modes (settings enum, default = c):** (a) auto-stop after 1 loop; (b) auto-add-layer (commit + open new layer at each boundary, hands-free until toggled off); (c) [DEFAULT] continuous until button press, snapped to integer loops — press schedules stop at NEXT loop boundary (assumed, confirm), so <1 loop behaves like auto-stop, longer extends the loop.

**RESOLVED:** mode (c) snaps to NEXT loop boundary. Period = max-of-layers, recomputed on delete (reverts when the extending layer is deleted). After extension, auto modes' span (word vs story) is SELECTABLE via setting/modifier. ALL DESIGN DECISIONS NOW CLOSED — ready to write the architecture/implementation plan.

# 2026-07 debugging on macOS / Bitwig 6.0.11 — CONFIRMED root causes (via host.println logging)

Environment: user moved Windows→macOS. Host API is v25 (extension still declares requiredAPIVersion 21 — fine). Confirmed mechanisms behind the flaky layer creation (temp `LOOPDBG` logging in LooperManager):
1. **`Channel.duplicate()` AND `duplicateObject()` (API 19) BOTH select the new copy.** No non-selecting duplicate works on a bank-window child track (`afterTrackInsertionPoint().copyTracks()` silently no-ops — needs a cursor anchor).
2. **The main bank scrolls to follow the selection regardless of the "Main track bank follows track selection" setting.** `createCursorTrack(...,shouldFollowSelection=false)` does NOT stop `createMainTrackBank` from scrolling to the newly-selected duplicate. That setting is a dead end for the looper.
3. **The record lands on the freshly-duplicated COPY, not the intended staging track.** `handlePad` calls `startRecording()` on the child[2] bank-POSITION proxy then duplicates the Template; by execution time the copy has slid into position 2, so recording goes into the copy → recorded clip ends up at child[2], original empty staging at child[3] (INVERTED ordering). This is the "beat-late"/"extra layer" confusion source.
4. **Extra layers = timing race:** the "child[2] is AUDIO+content → recreate staging" rule fires whenever a rescan catches a content-bearing layer at child[2] with pending=false — nondeterministic across async interleavings (repro differed run-to-run).
5. **MISCONFIGURED flicker:** right after a duplicate the copy is briefly named "Template"; a 2nd "Template" fails validity check #7, flashing the column MISCONFIGURED for several rescans. FINALIZE clears `pending` before the async rename lands, closing the tolerance window too early.
6. **Child bank is in heavy async churn** (~118 rescans at startup before children populated). All state is re-inferred from this churning bank each rescan.

ROOT CAUSE: stateless inference from a constantly-shifting child bank, PLUS addressing tracks by bank POSITION (no stable identity across a duplicate/insert). CHOSEN FIX DIRECTION (2026-07): address the operated group's children via a **pinned `CursorTrack`** (`CursorTrack extends CursorChannel, Track, PinnableCursor`; `isPinned().set(true)` decouples from selection; a pinned cursor pinned to the STAGING TRACK gives a non-position handle so `startRecording` can't bind to the moving copy). Cursors/banks are INIT-ONLY (Bitwig constraint) → cannot create one-per-child at runtime; use a bounded worker pool, repointed per operation. User wants UNLIMITED looper groups in ANY arrangement. Standing directive: NO timers.
